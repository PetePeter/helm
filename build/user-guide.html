Helm User Guide

Xbox controller → CLI session manager for AI coding terminals

1. Getting Started

Helm is a desktop app that lets you control multiple AI coding CLIs (Claude Code, Copilot CLI, etc.) from a single gamepad. Terminals are embedded — no external windows.

It runs on Windows (installer .exe) and macOS (universal .dmg — native on both Apple Silicon and Intel, no Rosetta).

First launch

  • Connect your Xbox controller (USB or Bluetooth)
  • Launch Helm — you'll see the session screen with the quick-spawn grid
  • Press D-Pad Up/Down to highlight a CLI tool, then A to spawn a session
  • Start coding with your controller as the input device
Generic / DirectInput gamepads are also supported. D-pad is detected via axes or hat switch automatically.

4. Sessions

Spawning sessions

  • Use the quick-spawn grid at the bottom of the session screen
  • Navigate with D-Pad, press A to spawn
  • Each CLI tool is a separate card in the grid

Session cards

Each session card displays:

  • Activity dot — indicates PTY I/O status:
    • Active (green) — producing output or receiving input
    • Inactive (blue) — silent for >10 seconds
    • Idle (grey) — silent for >5 minutes
  • Elapsed timer — time since last CLI output, refreshed every 10 seconds
  • Plan badges — coding + ready/blocked/review counts
  • Draft badge — count of unsent drafts

Groups

  • Sessions are grouped by working directory with collapsible headers
  • Group order and collapse state persist across restarts
  • Bookmarked directories appear as headers even with 0 active sessions (auto-bookmarked when a named session is removed)

Group overview

  • Press D-Pad → on a group header to open a scrollable preview grid
  • Each card shows: session name, terminal title, activity dot, last 10 lines of output
  • Navigate with D-Pad, press A to select, B to exit

5. Notifications

  • Bubble notifications — displayed when the AI agent uses notify_user
  • Notification carousel — per-session card, shows recent notifications
  • Clearing — press Ctrl+Shift+B to dismiss all notifications for the active session
  • Telegram mirror — PTY output is buffered during active periods and flushed to Telegram on activity change, question detection, or safety threshold (50 KB)
Telegram mirroring is activity-gated: only output produced during green-dot (active) periods is mirrored. Content is ANSI-stripped and noise-filtered before sending.

7. Plans

Plans are per-directory work items organized as an acyclic directed graph (DAG).

Lifecycle

planning→ ready→ coding→ review→ done | blocked
  • Planning — not ready or still being shaped
  • Ready — dependencies satisfied, available to claim
  • Coding — claimed by a session
  • Review — awaiting review
  • Blocked — requires resolution (see stateInfo)
  • Done — completed

Using plans

  • Open: click the &127758; button on a group header
  • Canvas shows nodes with dependency arrows, pan/zoom via mouse
  • Click a node to select it; editor panel at the bottom for title, description, and actions
  • Session cards display plan badges (coding + ready/blocked/review counts)
  • Claim a ready plan from the draft strip — click the ready chip to send its description to the terminal and transition to coding

8. Settings & Profiles

  • Open: click the &9881; button
  • Slides in as an overlay panel

Profiles

Each profile is a single YAML file containing:

  • Tools — CLI definitions, spawn commands, working directories
  • Directories — configured working directories
  • Bindings — per-CLI button mappings (keyboard, voice, sequence, spawn)
  • Patterns — regex rules for auto-actions
  • Stick / D-pad config — dead zones, sensitivity, mode

Switching profiles changes all bindings, tools, and patterns at once. Legacy tools.yaml / directories.yaml files are auto-migrated on first load.

9. Pattern Matcher

The pattern matcher scans every PTY output chunk against per-CLI regex rules defined in the profile.

Actions

TypeBehavior
send-textFires a sequence to the terminal immediately on match
wait-untilParses a scheduled time from the matched capture group, then fires the resume sequence at that time

Schedule management

  • When a wait-until rule fires, a &9200; chip appears on the session card
  • Cancelling: use the × button on the chip or pattern:cancelSchedule
  • Per-rule cooldown prevents rapid re-triggering

10. Artifact Viewer

Artifacts are readable reports an AI session produces for you — explanations, analyses, results — rendered inside Helm instead of leaving files for you to open. They are markdown or HTML, and the AI creates and updates them (via its MCP tools); you read, export, or delete them.

Opening the panel

HowWhat
📄 Artifacts toolbar buttonToggle the panel; shows a live badge with the count
Ctrl+Shift+AToggle the panel (ignored while a modal/editor/plan screen is open)
Edge tabWhen collapsed, a slim 📄 Artifacts tab sits on the right edge; it pulses when a new artifact arrives — click to open
×Close the panel

Layout

The panel docks on the right and is drag-to-resize (width persists). It is master–detail:

  • Index rail — scrollable list with search, sort (newest / recently updated / A–Z), Today/Earlier groups, and an unread dot on artifacts you haven't opened. Collapses to a thin handle.
  • Detail pane — the selected artifact, rendered.

Versions

  • When the AI updates an artifact it adds a new version; you can look back at earlier ones.
  • Use the ‹ › steppers or the version dropdown; an "older version" banner offers Jump to latest.

Diagrams

Fenced ```mermaid code blocks render as diagrams (dark theme). Mermaid loads on demand, only when an artifact actually contains one.

Images

Artifacts can show pictures — a screenshot the AI captured, a chart it generated, a diagram it exported. Two sources work:

  • Local files — a normal path (C:\reports\chart.png, ./out/graph.jpg) is served straight off your disk and appears inline.
  • Embedded images — data:image/… content baked into the artifact itself.
Remote images (http / https) and .svg are not rendered, deliberately: an artifact must never phone home to a server, and SVG can carry script. A blocked image shows as a plain broken-image placeholder.

Selecting text

Artifact text is selectable and copyable — drag to select, then Ctrl+C. While a selection is live inside the panel, Ctrl+C and Ctrl+X copy it instead of being forwarded to the terminal as an interrupt.

Export & delete

  • Export… — save the current artifact to a location you pick (this is the only way its content leaves the session).
  • Delete — remove the selected artifact. Clear all — empty the session's artifacts.

Snap-out

The panel is bound to its session, so when you snap a terminal out into its own window (the ⊡ pop-out), its artifacts travel with it — the panel appears in that window.

Lifecycle

  • Artifacts are ephemeral to the session.
  • Closing a recoverable session (one that can be restored) keeps its artifacts — restoring the session from the Recycle Bin brings them back.
  • They are cleared only when you Forget/Empty the session in the Recycle Bin, when a bin entry expires (30 days), or when a non-recoverable session is closed.

11. Recycle Bin

When a recoverable session (one that carried a resume id) is closed, it is kept for 30 days so you can bring it back — along with its artifacts.

  • Open: the 🗑 Recycle Bin button (Project Planner area, bottom-left) with a live badge count.
  • Entries sit in a collapsible tree — Project › Runtime Group › Folder › sessions. Runtime groups come first under a project, with a group chip on the row; folders that belong to no group sit directly under the project. Sessions Helm can't match to a project land under a catch-all node.
  • Each node carries a count of everything beneath it, and sessions are listed newest-closed first.
  • Rows show the session name, its CLI, the full working directory path, and the exact close time as yyyy/mm/dd HH:mm.
  • Search (name, CLI or path) filters the tree, keeping the branches that still contain a match.
ActionEffect
Restore ↺Re-spawns the session (reuses its original id, so its artifacts return)
Forget 🗑Permanently deletes that one entry (and its artifacts)
↺ Restore all / 🗑 Forget allPer-folder bulk actions on the folder header
Empty binClears every entry (and their artifacts)

13. Fleet (Cross-Machine)

Fleet lets one Helm drive another Helm on the same network. Once two machines are paired, an AI running here can create sessions, read terminals and manage plans over there. Fleet is off by default — nothing listens on the network until you enable it.

Turning it on

  • On both machines: Settings → 🔗 Fleet, tick Enable cross-machine fleet
  • The status line shows the addresses other machines can reach you on — click one to copy it
  • Both machines must allow TCP 47474 (and UDP 5353 for automatic discovery) through their firewall

Pairing

StepWhat to do
Find the other machineIt appears under Discover nearby — press Pair. If it never shows up, type its address into Pair by address (e.g. 10.98.1.140:47474)
Compare the codeA 6-digit code appears on both screens. Check they are identical
AcceptPress Confirm on both machines (A on the gamepad, Enter on the keyboard). The dialog confirms success and closes itself
Grant toolsOpen Allow-list on the new peer and pick a preset — Read-only, Sessions or All
A newly paired peer can do nothing until you give it an allow-list — that is deliberate. If remote calls are refused straight after a successful pairing, this is why.
If the two codes differ, press Reject. Matching codes are what proves you are talking to the machine you think you are, so a mismatch is the check doing its job — not a glitch to retry past.

Spotting remote-driven sessions

A session that a peer opened on this machine is tinted light blue in the sidebar, so you can tell at a glance which terminals are being driven from somewhere else. The tint survives hover, focus and restarts; a selected session still shows its usual accent border, and a flash for attention still overrides the tint while it runs.

Two-way conversations

An AI here can ask a question of an AI over there and get the answer back — the reply is delivered into the asking session as a normal inbound message, exactly as it would be between two local sessions. Nothing to configure; it follows from pairing.

Managing peers

ActionHow
Pause a peerThe On/Off toggle on its row — drops the live link and refuses it inbound, without unpairing
Change what it may doAllow-list — presets, or add patterns like session_*
See what it didAudit — a rolling 7-day log of every inbound call and its outcome
Remove itUnpair — forgets the key and the pinned certificate; pairing again starts from scratch
Closing a session, closing a group and restarting Helm can never be triggered remotely, even by a peer allowed everything.

14. Phone App

The Helm Android app is a companion for your sessions: read and answer them, get notified, call Helm by voice and send files — over Wi-Fi (LAN) at home or Bluetooth in the office. Everything is end-to-end encrypted between the phone and this PC.

Pairing

  • Install the APK from the GitHub release (the QR code in Settings points at the matching version)
  • Start pairing on the desktop, pick this PC on the phone, and check the 6-digit code matches on both screens before confirming
  • Wi-Fi is preferred automatically when both are on the same network; Bluetooth takes over when it isn't

Sharing a file to a session

StepWhat happens
ShareIn any app, Share → Helm
Pick a sessionThe phone lists your sessions; tap one
ResultThe file is saved in Helm's inbox on this PC and the session's draft gains Attached: <name> at <path>. Nothing is sent to the AI until you send the draft
Size limit: 10 MB over Wi-Fi, 2 MB over Bluetooth. Bigger files are refused on the phone before anything is sent.

15. Helm Operator & Voice

The operator is a single always-on session named Helm. You talk to it (by voice or chat) instead of picking a session: it answers questions about Helm and general questions itself (including web searches), and passes real work to the right session, then tells you the answer when it comes back.

Turning it on

  • Settings → 🎙 Operator: enable it and choose the CLI type and working folder
  • Changing the CLI type takes effect straight away: the old operator is demoted and unlocked (not closed, so no conversation is lost) and a fresh one starts on the new CLI
  • Rules: add your own rules, one per line — they rank above the built-in ones
  • The operator compacts itself about hourly when idle, so it stays fast

Talking to it

WhereHow
DesktopThe Helm section pinned at the top of the sidebar shows its last reply; start a hands-free call there (it listens until you pause, then sends)
Phone — Call HelmThe Helm tab: tap Call, speak, hear the reply. A short tone confirms each send. Hanging up or leaving the call screen releases the microphone
Phone — Hey HelmTurn on Hey Helm and say “Hey Helm” to start a call hands-free. Off by default
Hey Helm listens on the phone only (offline, nothing leaves the phone until it hears the wake word), but Android still shows the microphone indicator while it is on — that is expected. Turn it off to free the mic.
