Suggestion learning

When a session fetches a memory or skill that Helm recently suggested, Helm learns which topic terms tend to lead to useful items. Feedback is kept separate by project and only reorders that project’s eligible suggestions.

Privacy and effectItem ids, project id, topic terms, counts, and timestamps are retained. Prompt text and transcripts are not stored. A fetch counts only after a matching suggestion in the same session within 15 minutes. Older feedback has no project id and appears under “Unattributed legacy”.

Proposed structure

  • Move the existing feedback section from CLI Integrations here as “Suggestion learning”.
  • Break down both memory and skill feedback by the session’s project; “All projects” sums the project rows.
  • Use a searchable master list with project labels and a detail pane for terms and recent fetches.
  • Keep reset-all with confirmation. Historical global feedback remains unattributed until reset.

Recommended data boundary

Keep usage weights in the dedicated suggestion-usage store. They describe ranking behavior, not facts for AutoMemory to record. Store project id with each pending suggestion and apply its weight only in that project.

Approved change

Use single-select chips to show Both, Skill, or Memory items. The project selector remains independent, so each type can be inspected across all projects, one project, or Unattributed legacy.
