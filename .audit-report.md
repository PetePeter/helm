# Android UI audit — mockup vs shipped app

Method: read the mockup HTML (`helm-mobile-mockups.html`, source of truth) and every file under
`android/app/src/main/kotlin/com/potatomotato/helm/ui/`, then drove the live tablet (Lenovo TB-8505F,
`adb -s HA1R1HXP`) — screenshots + UI dumps of sessions, chat, control sheet, snapshot, and voice.
Proof screenshots: `.audit-*.png` in the repo root (untracked). No code written, no APK rebuilt,
nothing committed. `RECORD_AUDIO` was granted via `pm grant` (reversible) to reach the voice screen.

## Verdict

The foundation is **not** plainer than the mockup — tokens, true-black canvas, hairline elevation,
glowing state dots, SAS cells, chips and buttons all match near-verbatim. The gap is per-screen
**detail**, concentrated in screen 2 (chat) and screen 1 (list rows). Plus one functional bug found
on-device, and one user-reported bug (keyboard).

## Per screen

### 1 · Sessions — partial match
- ✓ Grouping exists (uppercase faint project headers — on-device first impression of "flat" was wrong).
- ✓ App bar: "Helm" + glowing dot + Linked. ✓ Dots with glow per state.
- ✗ **Unread badge** (accent pill + count) missing — `HelmType.Badge` is defined and used nowhere.
- ✗ **Relative time** on the right ("now" / "3m") missing entirely.
- ✗ **Status sub-line**: app shows only `cliTypeName` ("claude"); mockup wants "Implementing · claude"
  / "Needs your decision" / "Idle · 22m" — activity state + age.
- ✗ Row separators (#101013 hairlines) missing — whitespace only.
- ⚠ Extra: full-width "Pair a desktop" ghost button permanently under the app bar even while Linked.

### 2 · Chat — the biggest gap
- ✓ App bar (back, title, dot + Linked, ⋮), composer input + 40dp lime mic.
- ✗ **Own messages render as a grey `Surface2` bubble; the mockup's me-bubble is ACCENT #ccff00 with
  near-black text** — the single most recognizable element of the design, absent.
- ✗ AI bubble is `Surface` (#0b0b0d) with no border; mockup is `Surface2` (#121215) + 1px line border
  + asymmetric tail (15/5 radii). App: uniform radius, no border.
- ✗ **No timestamps in bubbles** — `Type.kt` defines labelMedium as "Timestamps"; nothing uses it there.
- ⚠ Extra "Send" text button beside the mic (mockup has none) — harmless, arguably useful.
- ✓ Delivery notes (Sending/Failed) under bubbles — good addition, keep.
- 🐞 **User-reported**: keyboard covers the composer and the conversation doesn't shift — edge-to-edge
  app with no IME inset handling (`imePadding`) and no scroll-to-bottom on keyboard open.

### 3 · Voice — structurally closest
- ✓ Status label, 112dp accent pulse, 12×3dp waveform bars driven by live level, editable transcript
  with accent cursor, ghost Cancel + primary Send in the lower third.
- ✗ No multi-ring glow halos around the pulse (mockup has 3 rings); app dims by alpha instead.
- 🐞 **On-device bug**: recognition fails immediately ("Recognition failed. Tap the mic to try again.")
  even with `RECORD_AUDIO` granted — likely no on-device recognizer / `EXTRA_PREFER_OFFLINE`
  unsatisfiable on this tablet. Needs investigation before polish matters.

### 4 · Session control sheet — close
- ✓ Hand-drawn sheet (surface, radius 20, 0.72 scrim, grab handle, hairline), danger Close +
  confirm-close flow, "checking…" → "not permitted" per the ratified greying.
- ✗ No icon tiles — mockup puts each glyph in a 29dp rounded-8 Surface2 box; app draws bare emoji at 2×.
- ✗ Greying is color-only; mockup adds 0.3 opacity.
- ✓ Drafts/Artifacts correctly absent per the ratified rule.

### 5 · Pairing — match
6 SAS cells (40×52, Surface2, hairline, mono accent), stacked match/reject + the Cancel added earlier.
Not re-drivable (already paired). No action.

### 6 · Lock screen — n/a
System-side notification styling (P-0746). Not an app screen; not drivable without locking. Skipped.

### 7 · Terminal snapshot — partial
- ✓ App bar (back + Snapshot; ⋮ doubles as refresh), chips 50/200/500/lines.
- ✗ No colored spans — every line is Dim; mockup has #c8c8d0 base + green/blue/amber highlights.
  `HelmType.Terminal` (11sp/18 mono) is defined and **unused** — `Tail` uses `bodySmall.copy(mono)`.
- ✗ Live snapshot content shows raw junk like `.[0 q.[0 q` — the desktop "stripped" tail isn't
  stripping these (OSC/cursor-query replies from codex?). Content hygiene, likely desktop-side.
- ⚠ Selected chip is an accent **fill** with dark text; mockup is accent **border** + accent text.

## Proposed plan (priority order)

1. **Chat order bug** — sort by arrival sequence, not clock skew (root cause above).
2. **Keyboard insets** — `imePadding` on chat (and any input screen) + auto-scroll to bottom when the
   IME opens.
3. **Chat fidelity** — lime me-bubble with OnAccent text; AI bubble Surface2 + hairline border;
   asymmetric tails; timestamps in bubbles.
4. **Session rows** — status sub-line (activity + age), relative time right, unread badge pill,
   separators. ⚠ WIRE QUESTION: does SessionSummary carry last-activity age + unread count over BLE?
   If not, that's an additive envelope change in `src/mobile/` — out of my scope until ruled.
5. **Sheet** — icon tiles; 0.3 opacity on forbidden rows.
6. **Voice** — pulse halos; separately investigate the recognition failure (AndroidSpeechEngine is in
   my scope; if the fix needs transport, it stops here).
7. **Snapshot** — switch `Tail` to `HelmType.Terminal`; color spans only if cheap (ANSI arrives
   pre-stripped, so spans may be desktop-side — decide then).
8. Minor — chip outline style, "Pair a desktop" only when unpaired, explicit ↻ refresh glyph.

Testable units: row-state formatting (sub-line text, relative time), badge visibility, chip selection,
bubble styling per sender, IME padding behavior. All unit-testable in `app/src/test`; the rest is
visual, proven by before/after screenshots.

## Live findings (user-reported, diagnosed)

- **Messages always out of order** — ROOT CAUSE FOUND: the tablet clock is **65 s behind** the PC
  (11:17:07 vs 11:18:12 UTC). `ChatRepository.append` sorts by `at`; outgoing messages are stamped
  with the PHONE clock, incoming ones with the DESKTOP clock, so every phone message sorts 65 s "in
  the past". Fix: order by local arrival sequence (the monotonic `key` already provides it), keep
  `at` for display only; a reconnect backlog still arrives in order from Helm. TDD-able, Android-side
  (data layer, no transport change).
- **"Not permitted" on spawn/close/compact** — was the desktop device allow-list (read/chat tools
  only). FIXED: granted `session_spawn`, `session_close`, `session_compact` via `mobile_device_allow`.
  The phone caches the answer until the BLE link drops (`CapabilityCache.forget()` on link loss), so
  the user must toggle Bluetooth off/on once for the sheet to re-ask.
- **Keyboard covers composer / conversation doesn't shift** — edge-to-edge app with no IME inset
  handling (`imePadding`) and no scroll-to-bottom when the keyboard opens.
